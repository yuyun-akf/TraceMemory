# 留痕记忆 TraceMemory

一个跟随聊天、而不是跟随角色卡的 SillyTavern UI 扩展。目标是让文字卡、MVU 卡和其他常见卡共用同一套懒人记忆流程，并把已经安全归档的旧楼层自动排除出模型上下文。

当前版本：`0.1.0-alpha.1`。这是首轮实机验证版，不把静态测试冒充手机酒馆已经验收。

## 三种模式

| 模式 | 额外 API 调用 | 短期记忆 | 长期归档 |
| --- | ---: | --- | --- |
| 同轮随写 | 0 | 主模型在正文末尾生成隐藏记忆包，扩展显示前剥离 | 满批时由同一次回复生成 |
| 后台总结 | 每个有效角色回复 1 次 | 使用酒馆当前连接静默总结 | 到达门槛时尽量在同一次后台结果中生成 |
| 混合归档 | 平时 0；满批时 1 次 | 同轮隐藏记忆包 | 满批后单独静默归档 |

后台调用复用酒馆已经配置的当前连接，不保存 API Key。

## 已实现

- 每个聊天独立启用、独立模式、独立记忆数据；新聊天自动初始化。
- 在已有长聊中首次启用时，只从当时的末尾开始接管；不会把启用前、尚未由本扩展总结的历史误当作已归档内容隐藏。
- 短期记忆、承诺、礼物、待完成／已完成约定、暗线伏笔、长期归档与角色日记。
- 默认每 15 条短期记忆归档；可改为 3—50 条。
- 归档成功后自动执行 `/hide`，默认保留最近 6 条消息。
- 只隐藏已经成功落盘归档的范围；从不删除正文。
- 每条由扩展隐藏的消息都有所有权标记；“恢复”只处理本扩展拥有的消息。
- 若旧楼被编辑、删除或重roll，立即停止继续写入／隐藏，并先恢复本扩展隐藏楼层，避免记忆与楼层错位。
- 同轮记忆包缺失或损坏时移出正文并加入“待补写”，不会在零调用模式下偷偷请求 API。
- 环境自检、记忆预览、漏记补写、到期归档、恢复隐藏楼层、导出与当前聊天重置。
- 0.1 版只在单人角色聊天中运行；群聊不会写入或隐藏。

## 安装边界

这份压缩包是 Git-ready 扩展源码，不是角色卡，不能在“导入角色卡”处打开。

SillyTavern 常规安装方式是把本目录放入一个可访问的 Git 仓库，再在扩展管理器的“安装扩展”里粘贴仓库地址。桌面端也可将整个目录放入当前用户的扩展目录后重载。不同 SillyDroid 分支的本地 ZIP 安装入口不统一，因此第一次先不要在珍贵长聊里试。

## 首轮手机验收（建议）

1. 新建一个专门测试的单人聊天，先关闭该角色卡原有的记忆区／变量记忆词条，防止两套记忆同时更新。
2. 打开扩展设置里的“留痕记忆”，点击“环境自检”。
3. 确认 `core`、当前所选模式需要的能力为 `true`；若 `autoHide=false`，扩展只会保存记忆，不会猜测隐藏接口。
4. 为了快速测试，把“每批条数”改成 3，“保留最近消息”改成 2。
5. 使用“同轮随写”完成 3 个有新剧情事实的角色回复；纯 OOC 不应增加条目。
6. 第 3 条后检查：长期归档变为 1 批；旧消息出现酒馆隐藏状态；最近 2 条仍可见。
7. 点击“恢复本扩展隐藏楼层”，确认正文全部回来。
   若仍开启“自动隐藏”，这些楼层会在下一批成功归档后再次进入隐藏范围；想让它们保持可见，请先关闭自动隐藏。
8. 重roll一条已经归档的回复，确认扩展显示“源消息变更锁”，停止自动隐藏而不是继续沿用旧记忆。
9. 再分别测试“后台总结”和“混合归档”，观察是否只产生表格所列次数的额外请求。

如果任一步不符合，请保留：环境报告、扩展面板状态、出错那一轮的生成类型和控制台错误。不要先手工改 JSON。

## 与角色卡原记忆区的关系

扩展自己的状态存放在当前聊天的 `chatMetadata.trace_memory_v1`，不会读写 MVU 路径，也不会要求卡内存在状态栏。因此文字卡可直接用，MVU 卡也可用。

但“兼容”不等于“两套同时开更好”。如果角色卡本身已经要求模型更新短期／长期记忆，测试本扩展时应先在卡的副本中关闭那几条记忆规则，否则会重复总结、重复占 token，甚至让两套归档门槛互相打架。角色的其他状态变量和状态栏可以继续使用。

## 安全原则

- 先保存归档，再隐藏来源；保存失败绝不隐藏。
- 只执行 `/hide` 与 `/unhide`，不执行删除指令。
- 不拥有原本已隐藏的消息，因此恢复时不会解除它们。
- 缺少宿主能力时关闭对应功能，不用猜测性的 DOM 点击或内部模块导入补洞。
- 记忆提示要求只收录明确事实，区分叙述、对白和隐藏心理，不替 user 推断动机。
- 记忆记录使用剧情内时间；剧情没有可靠时间时标为“时间未明”，不拿手机或服务器时钟冒充剧情日期。
- 扩展设置与记忆均不保存 API Key。

## 当前已知限制

- 尚未在用户实际的 SillyDroid 分支完成导入、重载、流式生成和 `/hide` 行为验收。
- 0.1 版不支持群聊写入。
- 修改或删除已经参与归档的旧消息会触发安全锁；当前处理方式是恢复隐藏并等待人工重置／修订，而不是自动重写历史归档。
- 超长聊天的旧归档会受“注入字符上限”约束；数据仍保存，只是不保证每批都同时送入单次提示。后续版本可加入检索式召回。
- 严格要求“只能输出某一种根标签”的角色卡可能排斥同轮记忆包；这类卡优先使用后台模式。
