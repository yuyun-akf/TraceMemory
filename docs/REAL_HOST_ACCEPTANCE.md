# SillyTavern／SillyDroid 实机验收

## A. 安装与生命周期

- [ ] 已通过同一 Git 仓库安装的 `0.1.0-alpha.1` 能在“管理扩展程序”中检测并更新到 `0.1.0-alpha.2`。
- [ ] 扩展管理器显示“留痕记忆 TraceMemory 0.1.0-alpha.2”。
- [ ] 原聊天的 `chatMetadata.trace_memory_v1` 在更新、刷新后仍能读取，已有记忆与当前聊天配置不丢失。
- [ ] 启用后设置面板只出现一次。
- [ ] 重载后设置仍在，控制台无重复监听报错。
- [ ] 禁用后提示注入清空、设置面板消失，正文和记忆数据不被删除。
- [ ] 再启用后当前聊天记忆仍可读取。

## B. 环境自检

- [ ] `readiness.core=true`。
- [ ] 同轮／混合模式前 `readiness.inline=true`。
- [ ] 后台／混合模式前 `readiness.background=true`。
- [ ] 自动隐藏前 `readiness.autoHide=true`。
- [ ] 报告只列接口名和版本，不含聊天正文或 API Key。

## C. 同轮随写

- [ ] 一个有效剧情回复增加恰好一条短期记忆。
- [ ] 纯 OOC 不增加。
- [ ] `<TraceMemoryUpdate>` 在消息渲染前消失，重载后也不出现。
- [ ] 漏包只进入“待补写”，没有额外网络请求。
- [ ] 第 15 条同轮生成一批长期记忆与日记。

## D. 后台与混合

- [ ] 后台模式每个待处理角色回复最多一次静默请求。
- [ ] 静默结果不成为聊天楼层，不再次触发记忆处理。
- [ ] 混合模式普通轮无额外请求，满批时一次静默归档。
- [ ] 后台失败时保留短期记忆和正文，不隐藏来源。

## E. 隐藏所有权

- [ ] 归档元数据保存成功前没有消息变为 `is_system=true`。
- [ ] 自动隐藏不碰索引 0，也不碰“保留最近消息”窗口。
- [ ] 在已有长聊中首次启用，只隐藏启用后已被本扩展归档的楼层，不触碰此前历史。
- [ ] 第二批归档会继续推进第一批留下的可见尾部，不出现永久漏藏区间。
- [ ] 已由用户手动隐藏的消息不获得扩展标记。
- [ ] “恢复”只解除带扩展标记的消息。
- [ ] `/hide` 或核验失败后，面板报告错误，没有伪报成功。
- [ ] `/hide` 部分成功时会尝试 `/unhide` 回滚；未能回滚的消息保留扩展所有权标记，仍可点击“恢复”重试。

## F. 变更与隔离

- [ ] 切换聊天后数据不串台。
- [ ] 编辑、删除或重roll未归档当前批消息时可安全替换或提示。
- [ ] 编辑、删除或重roll已归档来源时触发安全锁，并恢复本扩展隐藏楼层。
- [ ] 群聊中不写入、不注入、不隐藏。
- [ ] 同时开启卡内旧记忆规则时有可见冲突迹象；正式使用前关闭其中一套。

## G. 正文记忆栏与双向编辑

- [ ] 打开“在对应正文下显示记忆折叠栏”后，有记忆记录的角色回复下方出现“留痕记忆”折叠栏，且不进入正文编辑框。
- [ ] 关闭开关后所有正文记忆栏消失；重新打开后从后台数据恢复，记忆本身没有丢失。
- [ ] 在正文折叠栏修改一条未归档短记忆并保存，设置页“记忆编辑器”立即显示新内容；下一轮提示使用新内容。
- [ ] 在设置页修改同一条记忆并保存，对应正文折叠栏立即显示新内容。
- [ ] 一批归档显示在该批仍可见的来源回复下；任一处修改归档或日记后，其他位置同步刷新。
- [ ] 保存期间切换聊天，不把修改写到新聊天。
- [ ] 默认样式在手机窄屏可展开、输入和保存；按钮不溢出正文宽度。
- [ ] 自定义 CSS 应用、刷新后保留、恢复默认均正常；包含外部资源规则的 CSS 被拒绝。
