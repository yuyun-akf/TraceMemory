# 0.1 行为契约

## 目标行为

由浏览器端扩展拥有一份聊天级、角色卡类型无关的记忆状态。它在正常生成前注入紧凑记忆，在角色回复后更新状态，并仅在归档成功后隐藏已被该归档覆盖的旧消息。

## 状态所有权

- 全局默认值：`extensionSettings.trace-memory`。
- 当前聊天记忆：`chatMetadata.trace_memory_v1`。
- 隐藏所有权：消息 `extra.trace_memory_hidden_v1`。
- 提示注入键：`trace-memory.prompt.v1`。
- 角色卡 MVU、世界书、状态栏与其他扩展不属于本扩展所有，不得自动改写。

## 输入与输出

| 输入 | 输出／副作用 |
| --- | --- |
| 普通角色回复，同轮模式 | 剥离 `<TraceMemoryUpdate>`；把合法 JSON 写入聊天记忆 |
| 普通角色回复，后台模式 | 使用当前酒馆连接执行一次 `generateQuietPrompt`；正文不出现总结 |
| 满批，混合模式 | 执行一次后台归档；成功后可隐藏来源楼层 |
| 纯 OOC／规则讨论／无新事实 | 不新增短期记忆 |
| 包缺失／JSON 损坏 | 保留正文，记录待补写；同轮模式不自动额外调用 |
| 已归档来源被改／删／重roll | 安全锁定、停止写入和隐藏、恢复本扩展隐藏楼层 |

## 自动隐藏不变量

1. 没有已保存归档，绝不隐藏。
2. 归档只可覆盖其 `sources` 记录的实际消息区间。
3. 至少保留配置的最新消息数，且不自动隐藏索引 0 的开场消息。
4. 已经由用户或其他扩展隐藏的消息不取得本扩展所有权。
5. 恢复仅针对拥有 `trace_memory_hidden_v1` 标记的消息。
6. 任何 `/hide` 核验失败都撤销本次所有权标记并保留归档。
7. 不使用删除命令，不清除聊天正文。
8. 已有聊天首次初始化时，以当时聊天长度作为 `captureStart`；启用前且未经本扩展归档的历史不进入自动隐藏范围。
9. 每次成功隐藏从 `hidden.through + 1` 继续推进；恢复后游标回到 `captureStart - 1`，但不改动任何归档。

## 记忆证据边界

- 只记录当前叙事明确发生或明确说出的事实。
- 不把 user 的未说出口想法、Editor 旁白或隐藏心理改成角色知情。
- 不替 user 补动机、感受、同意、关系结论或恶意潜台词。
- 角色日记只写角色有合理信息来源知道的内容。
- 暗线可由叙事者记录，但不得据此让角色提前知情。
- `at` 使用模型从剧情中读取的时间；没有可靠剧情时间时使用“时间未明”。设备时间只保留为内部写入审计字段 `createdAt`。

## 兼容与失败策略

- 单人文字卡、MVU 卡和其他常见卡共用宿主聊天接口；卡内变量不是依赖。
- 群聊在 0.1 版 fail closed：不写入、不注入、不隐藏。
- 缺少 `generateQuietPrompt`：后台和混合归档不可选；同轮模式仍可用。
- 缺少可识别的聊天保存函数：同轮与混合模式不注入记忆包，避免刷新后包重新出现。
- 缺少 slash 执行接口：记忆照常保存，自动隐藏停用。
- 缺少核心上下文、事件、聊天元数据或元数据保存：整条链路停用。

## 验证门槛

- 静态：清单合法、JS 语法通过、纯函数测试通过、能力契约样例通过、压缩包内容审计通过。
- 实机：扩展可安装／启停／重载；三种模式调用次数正确；记忆包不出现在正文；聊天切换不串数据；满批隐藏与恢复正确；旧楼变更触发安全锁。

静态检查通过不能替代实机门槛。
